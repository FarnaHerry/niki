# hui — HuxerUI 拖拽设计器（GUI + CLI + MCP）

**用 HuxerUI 做 HuxerUI 的界面，逻辑用 C++23。**

hui 是一个仿照 Qt Designer 的可视化布局工具：把 HuxerUI 组件拖进画布、就地编辑属性，
实时得到一份可提交的 `.hui.json` 布局文档和可直接编译的 HuxerUI C++ 模块代码。
同一个引擎同时以三种方式暴露：

| 入口 | 用途 |
|---|---|
| `hui`（GUI） | 人：拖拽画布 + 组件面板 + 属性检查器 + 结构树 + 代码预览 |
| `hui <子命令>`（CLI） | 人 / 脚本 / CI：建文档、校验、生成代码、查目录、自检 |
| `hui mcp`（MCP 服务器） | AI：读组件目录、批量改文档、校验、生成代码 |

三者共享同一套核心（C++23 modules，`src/core/`），文档即契约。

## 构建与运行

标准的 HuxerUI CMake 工程（与 apitab、llm-switch 同形）。依赖相邻路径下的 HuxerUI
源码（`third_party/huxerui` → `../../HuxerUI`），也可用 `-DHUXERUI_HOME=<路径>`
指向别处的源码或已安装 SDK：

```bash
cmake -S . -B build -G Ninja
cmake --build build --parallel 8

./run.sh        # 构建并打开设计器
./build/hui     # 已构建时直接运行
```

CLI / MCP 用法（二进制就是 `build/hui`）：

```bash
hui                 # 无参数 = 打开设计器 GUI
hui help
hui new LoginPage -o examples/login.hui.json
hui validate examples/*.hui.json
hui codegen examples/counter.hui.json                 # 完整模块单元 → stdout
hui codegen examples/counter.hui.json --style snippet # return 语句片段
hui catalog            # 人读的组件目录
hui catalog --json     # 机器读的完整 schema
hui selftest           # 核心逻辑自检
hui mcp                # stdio MCP 服务器
```

构建分层：`src/core/` 与 `src/cli.cppm` / `src/mcp.cppm` 是 C++23 模块（`import std;`），
`src/ui/` 与 `src/app.cpp` 是普通的 `#include <huxerui/huxerui.h>` 源文件（`hcg` 负责
`[[huxerui::composable]]` 变换）。每个翻译单元都把 `#include` 写在 `import` 之前。

## 设计器（GUI）

```
┌─ hui  counter_page │ ⟳ New Open Save Export │ Undo Redo ──── [◐][—][□][×] ┐
│ counter_page.hui.json • │ login.hui.json │ +                              │
│ 组件面板   │            画布（真实组件实时渲染）        │  检查器  │
│ (拖拽源)   │  拖进容器 / 点选 / 拖动已有节点重新布置     │  属性    │
│ ────────  │  选中后八点拉伸                            │  修饰符  │
│ 结构树     │  代码面板：C++ / JSON 双页签 + Copy        │  事件    │
│            │                                            │  问题列表 │
└─ 状态栏 ──────────────────────────────────────────────────────────────┘
```

标题栏一行就是全部窗口操作：左边是名字 + 文档名 + 文件/编辑动作（New / Open / Save / Export / Undo / Redo），
右边是主题与最小化/最大化/关闭。所以窗口只有两条 chrome：**标题栏**和**标签页条**。

- **标签页即文件**：每个标签页显示它对应的文件名，一个标签页一份 `.hui.json`，没有单独的路径输入框。
  `+` 新建一页（此时还没有文件，`Save` 会按页名生成一个并把名字显示到标签页上）；
  `Open` 走系统文件对话框，读进**新**标签页（该文件已经打开则切过去，不开第二份）；
  悬停标签页可以看到完整路径。
- **切换标签页换整套状态**：画布、结构树、撤销历史、未保存标记都跟着换——每个页面各自持有文档、历史与选择。
- **画布即真件**：文档里的每个节点都用真正的 HuxerUI 组件渲染——你在设计器里看到的就是用户看到的样子。
- **拉伸**：选中一个节点后，它的四角与四边中点会出现八个把手，拖动即改这个节点的 `width` / `height`
  修饰符（下限 8px）。把手由自定义布局 `ResizeFrame` 按节点的**实测尺寸**摆放，所以没有显式宽高的节点
  也能从「现在多大」开始拉伸；整段拖动只产生**一次**撤销记录。
- **拖拽**：按下即拖（超过指针 slop 就开始），没有长按等待。面板卡片拖到容器上新增——组件只能靠**投放**落地，
  不存在「单击猜一个目标位置」的动作；画布里的节点拖到别的容器就搬家，按下后不动则只是一次选中。
  拖动时跟着指针的是**节点自己**（不带选中描边等编辑器装饰的成品样子），不是一个小标签替身；
  面板卡片还没有「当前样子」，所以仍用图标 + 类型的小预览片。
- **就地编辑**：选中节点后右侧检查器按组件目录生成编辑器——属性（文本/数值/布尔/枚举/选项列表/颜色）、
  修饰符（padding/width/height/grow/圆角/前景背景边框/字号/enabled）与事件（开关绑定 + 填 handler 名，
  留空则生成 TODO 占位 lambda）。没有选中时检查器编辑的是文档本身（模块名）。下面常驻**问题列表**，
  直接跑 `hui.core.validate`，错误/警告分色，并带节点 id。
- **节点操作**：检查器里可以上移/下移（改变在兄弟中的次序）和删除；根节点不提供这两个动作。
- **代码岛**：底部 `C++ / JSON` 双页签实时反映当前页面，右上角 Copy 把当前页签的内容写进剪贴板
  （C++ 是导出内容本身，JSON 是 `hui.core.docio` 的序列化结果）。
- **导出**：`Save` 写页面自己的 `.hui.json`（`•` 表示有未保存改动）；`Export` 在同一个位置生成同名 `.cppm` 模块文件。
- 空容器有 "drop children here" 占位提示；根节点是叶子时画布会提示无处可放。
- **快捷键**：`Delete` 删除选中节点（根节点删不掉，会提示原因）；`Ctrl+Z` 撤销，`Ctrl+Shift+Z` 重做。
  在输入框里打字时这三个都不生效——焦点在文本字段上时按键归字段所有。
- 最后一个标签页关不掉：关掉它会就地开一份新文档，所以永远有一页可编辑。

画布对 `ScrollView` 固定给了 240 高度便于预览；生成代码不含该约束，由你的应用自行给滚动区边界。

## 布局文档（`.hui.json`）

```json
{
  "format": "hui/1",
  "name": "CounterPage",
  "root": {
    "id": "n1", "type": "Column",
    "props": { "spacing": 12.0 },
    "modifiers": { "padding": 24.0 },
    "children": [
      { "id": "n2", "type": "Text", "props": { "text": "Count: 0", "role": "Title" } },
      { "id": "n3", "type": "Row", "props": { "spacing": 8.0 },
        "children": [
          { "id": "n4", "type": "Button", "props": { "label": "Increment" },
            "events": { "onClick": "OnIncrement" } },
          { "id": "n5", "type": "Spacer" }
        ] }
    ]
  }
}
```

- 节点 id 在文档内唯一且稳定（`n1`, `n2`, …），AI 与 GUI 的操作都以 id 寻址。
- 未写的属性 = 组件目录里的默认值；颜色为 `#RRGGBB` / `#RRGGBBAA`。
- `Column/Row/Flow/Stack` 任意子节点；`ScrollView` 与各 Theme 组件单子节点；其余为叶子。
- `events` 把事件名映射到处理函数名：每个节点都能绑 `onClick`，输入组件另有
  `onChanged`（Checkbox/Switch/RadioButton/Chip 是 `void(bool)`、Slider 是 `void(float)`、
  Select 是 `void(std::size_t)`、TextField 是 `void(const TextEditingValue&)`）、
  Slider 的 `onCommitted`、TextField 的 `onSubmitted`。handler 名必须是 C++ 标识符并被原样
  写进生成代码；写空字符串表示"先占位"——生成一个可编译的 TODO lambda。完整列表见
  `hui catalog --json` 里每个组件的 `events`。
- 支持的组件与全部属性：`hui catalog --json`。

### 生成的代码

```
hui codegen counter.hui.json
```

```cpp
// Generated by hui 0.1.0 from counter.hui.json. Edit the document, not this file.
export module counter_page;

import std;
import huxerui;

using namespace huxerui;

export View CounterPage() {
  return Column {
    Text("Count: 0", TextRole::Title),
    Row {
      Button("Increment").OnClick(OnIncrement),
      Spacer(),
      Button("Reset").OnClick(OnReset),
    }.With(Spacing(8.0F)),
  }.With(Padding(24.0F), Spacing(12.0F));
}

// hui: this document binds handlers the enclosing scope must provide (the generated module
// does not define them). Declare them in this module, or import them, then implement them.
//   void OnIncrement();                          // Button n4 onClick
//   void OnReset();                              // Button n6 onClick
```

风格遵循 HuxerUI 仓库的 DSL 约定（花括号容器、`.With(...)` 链、`24.0F` 字面量）。
绑定了命名 handler 时，生成文件末尾会列出必须由应用提供的函数签名；把它们声明/实现进
这个模块即可。空 handler 的绑定的则生成 `OnClick([]() { /* TODO */ })`，无需应用侧代码
就能编译。把生成的 `.cppm` 放进任意 mcpp 应用（`import counter_page;`）即可使用。

## MCP：让 AI 帮你搭界面

`hui mcp` 在 stdio 上讲标准 MCP（JSON-RPC 2.0，按行分帧）。工具：

| 工具 | 作用 |
|---|---|
| `hui_catalog` | 全量组件 schema（属性/枚举/默认值/子节点策略）+ 文档格式说明 |
| `hui_new_document` | 生成起始文档 |
| `hui_apply` | **批量**应用 add / update / remove / move / shift / rename 操作（含 props / modifiers / events），返回更新后的文档 + 校验 |
| `hui_validate` | 校验文档，返回带节点 id 的问题列表 |
| `hui_outline` | 紧凑的树状大纲（重读文档的廉价方式） |
| `hui_generate_code` | 生成 `module` 或 `snippet` 风格的 C++ |

资源：`hui://catalog`（组件目录）、`hui://format`（格式说明）。

接入支持 MCP 的客户端（以 Claude 风格配置为例）：

```json
{
  "mcpServers": {
    "hui": {
      "command": "/绝对路径/target/x86_64-linux-gnu/<hash>/bin/hui",
      "args": ["mcp"]
    }
  }
}
```

一个 AI 搭建完整页面的典型会话：`hui_catalog` → `hui_new_document` →
一条 `hui_apply` 提交十几个操作 → `hui_validate` → `hui_generate_code`。
保存返回的 document JSON 为 `.hui.json` 即可继续在设计器里手工微调——人机共用同一份文档。

## 工程结构

```
CMakeLists.txt       顶层构建（huxerui_add_app + 引擎的 CXX_MODULES file set）
run.sh               构建并运行 build/hui
platform/linux/      平台入口（无参数=GUI，有子命令=CLI）与打包资源
src/core/            纯逻辑（C++23 模块，只 import std）：
  json.cppm            内建 JSON（有序对象、解析/紧凑/美化输出）
  catalog.cppm         组件目录（面板/检查器/校验/代码生成/MCP 共用的唯一事实源）
  doc.cppm             文档模型 + 纯操作（增删移改、历史/撤销重做）
  docio.cppm           文档 ⇄ JSON ⇄ 文件
  validate.cppm        校验（error/warning，带节点 id）
  codegen.cppm         文档 → HuxerUI DSL C++（含事件绑定与 handler 清单）
src/cli.cppm         CLI 子命令 + selftest
src/mcp.cppm         MCP 服务器（stdio JSON-RPC）
src/ui/              设计器界面（普通头文件 + .cpp，import 引擎模块）：
  ui.h                 前端全部声明：Editor 共享状态、Page（一页=一份文件）、拖拽 payload、各面板入口
  theme.h              设计器自身的深浅色调色板
  icons.h/.cpp         24×24 矢量图标（随主题着色，不需要两套资源）
  resize.h/.cpp        拉伸把手：实测尺寸表（NodeMetrics）、尺寸探针（SizeProbe）、八点布局（ResizeFrame）
  widgets.h/.cpp       受控字段词汇（文本/数值/布尔/枚举/列表），composable 定义在 .cpp
  editor.cpp           页面模型：新建/打开/保存/导出/撤销重做，所有页面改动经 Editor::Edit 提交
  inspector.cpp        检查器：属性/修饰符/事件 + 节点上下移与删除 + 问题列表
  codepanel.cpp        代码岛：C++ / JSON 双页签 + 复制
  tabs.cpp             标签页条（文件名 + 未保存标记 + 关闭 + 新建）
  canvas.cpp           画布：文档实时渲染、选择、拖放、八点拉伸
  palette.cpp          组件面板（拖拽源）
  structure.cpp        结构树（可拖拽重定位，⚡ 标记已绑定事件的节点）
src/app.cpp          应用壳（标题栏、标签页、工具栏、岛屿布局、Application 注册）
resources/           打包资源
examples/            示例文档（counter / login / profile_card，均含事件绑定）
```

核心与界面严格分离：`src/core` 不依赖 HuxerUI，CLI 与 MCP 完全无头运行。

> mcpp 时代的实现（`mcpp.toml` / `build.mcpp` / 模块化 UI / 画布早期步骤）在 git 历史里，
> 见 `b1eba51`；工作区只保留当前这一套。

## 当前范围与后续

v0.2 目录覆盖 HuxerUI 的布局、内容、输入与主题组件（21 个）、常用修饰符（11 个），
以及事件绑定：每个节点可绑 `onClick`，输入组件另有 `onChanged` / `onSubmitted` /
`onCommitted`，命名为 handler 时生成可直接编译的 `.OnClick(Handler)` 链并在文件末尾列出
签名清单，留空时生成可编译的 TODO 占位 lambda。

有意留待后续：更多事件（`On<...>` 上的指针/键盘/生命周期事件）、列表虚拟化组件
（VirtualList/Grid）、导航壳（TopAppBar/NavigationPane）、图片资源、
把多份页面串成一个可导航的工程（现在一个标签页一份文档，但还没有页面之间的跳转模型）、
以及 C++ → 文档的反向解析。

## 上游待办

**自定义标题栏需要框架配合**。`WindowChromeMode::Custom` 下框架仍然绘制最小化/最大化/关闭，
并会在 Linux 上为它们预留一段右侧内缩。本仓库给 `WindowOptions` 加了 `caption_controls`：
应用声明 `WindowCaptionControls::Application` 时框架不再绘制、也不再预留。改动目前以本地补丁
的形式留在 HuxerUI 检出里（`third_party/huxerui` 指向 `../../HuxerUI`，6 个文件），
提 PR 被接受后即可删除。
